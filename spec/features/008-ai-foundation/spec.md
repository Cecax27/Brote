## 008 - AI Foundation

**Status:** Planning

## What makes

The app gets its plant companion. Flora stops being a placeholder and starts talking — through `brote-agent`, a separate Python + Gemini service on Google Cloud Run. This feature lays every wire Flora needs: a typed agent client, the persistence layer, the Flora visual identity, and the chat surface. It is deliberately scoped to *general and per-plant text chat*; vision-based species ID (`009`) and symptom diagnosis (`010`) build on top of this foundation.

- **brote-agent client** — a typed wrapper over the agent's HTTP contract (`GET /health`, `POST /chat`). It is mockable so the chat UI, persistence, and Flora art all ship before the agent is live. It maps the agent's error envelope (`VALIDATION_ERROR` 422, `UPSTREAM_ERROR` 502, `INTERNAL_ERROR` 500) into a typed `AgentError` the UI can render as a calm Spanish line — never a crash, never a red banner.
- **Persistence — `ai_conversations` + `ai_messages`** — two Supabase tables owned by the user. A conversation is optionally rooted at a plant (`plant_id` nullable). The agent itself is stateless; the app owns the memory. Every user and assistant message is saved as it's produced, so conversations resume on app re-open and feed `010`'s richer context later.
- **Flora visual identity** — Flora is a watercolor flower, never a mascot. A `FloraAvatar` component renders the four illustrations in `assets/images/illustrations/Flora/` by mood (idle / rainy / hot / confused), per `brote-visual-guide`. The plan replaces the `MaterialCommunityIcons` placeholder used by `Illustration name="flora"` on the home screen and plant detail with the real watercolors.
- **Chat UI** — message bubbles (assistant left / user right), a calm three-watercolor-leaf typing indicator (Reanimated, per the visual guide), a plant-context header when the conversation is rooted at a plant, and an input bar. Slow, breathing animations; sage + warm-white palette; generous whitespace. "Does this invite me to stay five more minutes?" is the gate.
- **Chat list** — `/chat` lists a user's conversations, newest first, each row showing its Flora avatar (or a plant thumbnail when rooted), title, and last-message preview. "Nuevo chat" starts a general conversation; "Ask about this plant" on the plant detail starts a plant-rooted one. The home "Hablar con Flora" button (currently a no-op) opens the list.
- **Context builder** — assembles a compact `PlantContext` (plant info + recent journal entries) from Supabase and sends it alongside the message. The plan pins the request shape as an extension of the agent contract (`{ message, context? }`) so the agent can ignore `context` until it's ready and the JSON stays backward-compatible. System-prompt engineering lives server-side in brote-agent; the app only gathers the data.
- **Auth boundary** — the app sends the Supabase session access token as `Authorization: Bearer <jwt>` on every `/chat` call. The agent verifies it (no client-bundle secret; no anonymous calls to the model). The foundation wires the header; agent-side verification is the agent's responsibility.
- **Loading / empty / error states** — every screen has a calm state for each. The empty chat list reads as "Aún no has hablado con Flora"; an empty conversation shows a Flora welcome card; an agent error is surfaced inline ("Flora no pudo responder ahora. Inténtalo de nuevo."), never as an alarm.

## Why

The roadmap banner for V0.3 says *"all AI features are served by brote-agent"*. `008` is the seam that connects Brote to brote-agent — without it, `009` (plant ID) and `010` (consultation) have nothing to ride on. Doing it first means the agent and the app can move in parallel: the agent finalizes its endpoints against this contract while the app ships the chat surface against a mock, then they meet.

The foundation intentionally stops at *text chat*. Plant identification (`009`) needs a vision endpoint the agent hasn't exposed yet; consultation (`010`) needs the richer context builder and the "every reply ends in a concrete action" rule. Keeping `008` to the persisted chat loop leaves those features room to define their own endpoints and prompt engineering without re-litigating the data layer.

Conversations are persisted because Flora's promise — *"she knows the complete history of every plant"* — is impossible without memory. The mission says the AI is "a permanent companion," and a companion you forget everything overnight isn't one. Putting the memory in Supabase (not the agent) keeps Brote self-owned: the user's plant story lives in their database, and the agent is a stateless brain that reads what the app hands it per request.

Flora's visual identity lands here because chat is where Flora *appears*. The four watercolor illustrations in `assets/images/illustrations/Flora/` already exist and map cleanly to mood states; the visual guide says Flora "appears only when speaking," and chat is the speaking surface. Replacing the placeholder ` flower` glyph now — with the rush to ship chat — is the cheapest moment to do it, and it keeps the chat empty/error states consistent with the rest of the app from day one.

The `brote-visual-guide` typing indicator ("three tiny watercolor leaves animate in place of the classic three-dot typing indicator") is honored literally: Flora is a flower, so when she's thinking we see leaves, not dots. It is the kind of detail that answers the constitution's parting question — *"would I want to stay five more minutes?"*

## Acceptance criteria

1. A numbered Supabase migration creates `public.ai_conversations` with columns `id (uuid pk, default gen_random_uuid())`, `user_id (uuid not null references auth.users (id) on delete cascade)`, `plant_id (uuid null references public.plants (id) on delete cascade)`, `title (text not null default 'Conversación con Flora')`, `created_at (timestamptz not null default now())`, `updated_at (timestamptz not null default now())`. A `handle_updated_at` trigger is attached (the trigger function already exists from `001`).
2. The migration creates `public.ai_messages` with columns `id (uuid pk)`, `conversation_id (uuid not null references public.ai_conversations (id) on delete cascade)`, `role (text not null check (role in ('user','assistant')))`, `content (text not null check (char_length(content) between 1 and 4000))`, `photo_url (text null)`, `created_at (timestamptz not null default now())`. No `updated_at` column — messages are immutable. No `user_id` column — ownership is inherited via the conversation (`ai_messages` is reached only through a conversation the user owns).
3. RLS: `ai_conversations` gets `ai_conv_owner_select/insert/update/delete` (`auth.uid() = user_id`); `ai_messages` gets `ai_msg_owner_select/insert/update/delete` using `auth.uid() = (select user_id from public.ai_conversations ac where ac.id = ai_messages.conversation_id)`. A user may never read or write another user's conversation or messages.
4. Indexes: `ai_conversations(user_id, created_at desc)` for the chat list, `ai_messages(conversation_id, created_at)` for the message thread. After applying the migration, `npm run gen-types` is run and committed so `Database["public"]["Tables"]["ai_conversations"]` and `["ai_messages"]` resolve under TypeScript strict mode.
5. `src/lib/supabase/ai-conversations.ts` exposes typed helpers that throw on error (raw Supabase error, except `PGRST116` → `null`): `fetchConversations()`, `fetchConversation(id)`, `createConversation({ plant_id?, title? })`, `updateConversation(id, { title })`, `deleteConversation(id)`. `fetchConversations` joins plant via `select("*, plants(*)")` and returns `ConversationWithPlant[]`. `deleteConversation` cascades to its messages (FK).
6. `src/lib/supabase/ai-messages.ts` exposes typed helpers that throw on error: `fetchMessages(conversationId)`, `createMessage({ conversation_id, role, content, photo_url? })`. Inserting an assistant message reuses the same helper with `role: "assistant"`. A `ConversationMessage = Tables<"ai_messages">` alias is exported. No update/delete helpers in V0.3 — messages are immutable.
7. `src/lib/agent/client.ts` exports an `AgentClient` interface and a `createAgentClient({ baseUrl?, fetch? })` factory reading `process.env.EXPO_PUBLIC_BROTE_AGENT_URL!` by default. It exposes `getHealth(): Promise<{ status: "ok" }>` (GET `/health`) and `postChat(input: AgentChatInput): Promise<string>` (POST `/chat`, returns the `reply` string). `AgentChatInput` is `{ message: string (1–2000 chars, validated client-side); context?: PlantContext }`.
8. The agent client authenticates via the Supabase session: `postChat` accepts an `accessToken: string` argument and sends `Authorization: Bearer <accessToken>` on every request. The client may be constructed with a mock `fetch` and a fixed `baseUrl` for tests; a `MockAgentClient` (exported from `src/lib/agent/mock.ts`) returns canned Spanish replies without a network, so the chat UI ships before the agent is live.
9. The agent client maps the agent's error envelope into a typed `AgentError` with `code: "VALIDATION_ERROR" | "UPSTREAM_ERROR" | "INTERNAL_ERROR" | "NETWORK"` and a Spanish `message`. A 422 → `VALIDATION_ERROR`, 502 → `UPSTREAM_ERROR`, 500 → `INTERNAL_ERROR`, a network/`AbortError`/non-JSON body → `NETWORK`. The UI renders the message inline and never crashes.
10. `src/lib/agent/context.ts` exports `buildPlantContext(plantId: string): Promise<PlantContext>` and a `PlantContext` type bundling `{ plant: Plant, recentEntries: JournalEntry[], schedule?: WateringSchedule }` (recent = last 10 entries by `created_at desc`). It is called when a conversation has a `plant_id` (cached per conversation). A general conversation sends no context (`undefined`). The shape is documented as the app→agent data contract; the agent may ignore `context` until it implements use of it.
11. A `FloraAvatar` component renders the watercolor PNGs in `assets/images/illustrations/Flora/` via `expo-image`. Props: `mood: "idle" | "rainy" | "hot"` (or `constused`), `size?: number` (default 72), `style?`. Mood mapping: `idle` → `Simple Flora.png`, `rainy` → `Flora in rain.png`, `hot` → `Hot flora, in a warmer day.png`, `confused` → `Flora with a confused expression, as if she were in doubt.png`. No cartoony features; no human figure; per `brote-visual-guide`. The home `Illustration name="flora"` and the plant detail `EmptyState illustration="flora"` are updated to use `FloraAvatar` (or the underlying watercolor) instead of the `MaterialCommunityIcons` `flower` glyph.
12. A `ChatMessageBubble` component renders one message: assistant rows align left with `colors.surface` bubble + `FloraAvatar size=28` beside them; user rows align right with `colors.primary` bubble + warm-white text. Bubble radius `radii.card` + light `shadows.resting`. Body text uses `typeScale.body`; long messages scroll. No hard-coded colors — all from `useTheme()`.
13. A `FloraTypingIndicator` component animates three small sage leaves (Reanimated v4, opacity + slight `translateY`, `motion.duration.slow` 450ms, ease-in-out, staggered by `motion.duration.micro` 200ms). Used while awaiting the agent reply. Never uses three dots.
14. A `ChatContextHeader` component renders the plant context line when a conversation is rooted at a plant: the plant thumbnail, "Hablando sobre {name}" (Fraunces `h3`), and a chevron disc… hidden for general conversations.
15. A `ChatInput` component renders the input bar: a `TextInput` (multiline up to 5 lines, char counter at >1900, disabled while a reply is pending), a sage send `Button`, and a clear stop… Terms: reads in Spanish with a calm "Escribe a Flora…" placeholder.
16. Routes (file-based, registered in `src/app/(app)/_layout.tsx` with Spanish titles): `/chat` (title "Flora") lists the user's conversations; `/chat/new` (title "Nuevo chat") optionally takes the encoded query param `plantId` to root the new conversation at a plant and on first send creates the `ai_conversations` row then `router.replace("/chat/[id]")`; `/chat/[id]` (title "Flora") loads messages and persists sends. `typedRoutes` is on (see `app.json`), so the route map regenerates from these files.
17. The home screen's "Hablar con Flora" button (`src/app/(app)/index.tsx`, currently `onPress={() => {}}`) becomes `router.push("/chat")`. The plant detail screen's bottom `EmptyState illustration="flora" ... "Próximamente"` (`src/app/(app)/plants/[id]/index.tsx`) becomes a `Button variant="secondary"` "Consultar a Flora" that pushes `router.push({ pathname: "/chat/new", params: { plantId: id } })`.
18. Send flow on `/chat/[id]`: optimistically append the user message (with `role: "user"`, optimistic `id`), persist via `createMessage`, render the typing indicator, call `agent.postChat(message, context?, sessionAccessToken)`; on success append the `assistant` message, persist via `createMessage({ role: "assistant", content: reply })`, stop the typing indicator; on `AgentError` show a calm inline Spanish error above the input and keep the user's last message so they can resend. The conversation's `title` derived from the first user message (truncated to ~30 chars) is written once via `updateConversation` on the first successful exchange.
19. Loading / empty / error states: `/chat` shows `LoadingSkeleton` while fetching; an `EmptyState` (illustration `FloraAvatar idle`) "Aún no has hablado con Flora" + a "Empezar a hablar" action when the list is empty. `/chat/[id]` shows `LoadingSkeleton` while fetching messages; the empty conversation state shows a `FloraAvatar idle` welcome card with the line "Hola, soy Flora. Pregúntame lo que quieras sobre tus plantas." and the input bar ready. Agent errors render inline as in criterion 9 — never a full-screen error wall.
20. All Supabase access goes through the typed client and RLS. The app never reads or writes another user's conversations or messages. The agent client never embeds a Gemini key or any AI provider credential; the only credential on `/chat` is the Supabase session JWT, which already exists in the auth context. No secrets land in the bundle.
21. Visual style follows the `brote-visual-guide` and theme tokens throughout: warm-white background (`colors.background` `#F8F6F2`), brown-black body text (`colors.text.primary` `#3F3A36`), sage primary (`colors.primary` `#6E8E6A`), Fraunces for titles, Inter for body, radii ≥ 16, soft shadows, slow (200–450ms) fade/scale micro-interactions via Reanimated. No emoji as icons; line-art MaterialCommunity icons only. No pure black or white anywhere.
22. `npm run lint` passes with no errors.
23. `npx tsc --noEmit` passes under strict mode (regenerated types resolve `AIConversation`, `ConversationMessage`, and the agent client interfaces).
24. Manual: on a fresh app, `/chat` is empty with the "Aún no has hablado con Flora" empty state → "Empezar a hablar" navigates to `/chat/new` → sending "Hola" produces a welcome reply from Flora; the conversation appears on `/chat` on return; re-opening it shows the persisted messages and an input bar.
25. Manual: from a plant detail, "Consultar a Flora" opens `/chat/new?plantId=…`; the conversation's context header shows the plant name and thumbnail; the persist + send flow works identically; the conversation appears on `/chat` rooted at that plant (row shows the plant thumbnail where a general chat shows `FloraAvatar`).
26. Manual: against the `MockAgentClient` (no `EXPO_PUBLIC_BROTE_AGENT_URL` set or a `__forceMock` flag), the full chat loop still works end-to-end — messages persist, the list and conversation screens render, the typing indicator plays and resolves — so the feature is shippable before brote-agent is live.

## Out of reach

- **Plant identification from a photo (`009`)** — needs a vision endpoint on brote-agent (`POST /identify` or similar) that doesn't exist yet. `008` only ships text `/chat`. The agent client is typed so adding `identifyPlant(input)` is a one-method extension.
- **Symptom diagnosis + "always end in a concrete action" rule (`010`)** — needs richer context (light history, watering adherence, photos) and stronger system-prompt engineering on the agent side. `008` ships the context builder with plant + recent journal only; `010` extends it.
- **The agent's `/chat` replies being correct/diagnostic** — out of scope for this *app* spec. Gemini prompt engineering, system instructions, and reply quality live in brote-agent (Py); `008` only certifies that Brote sends `{ message, context }` and renders the returned `reply` correctly.
- **Agent→model vendor swap (Gemini↔OpenAI)** — server-side only, invisible to the app; handled in brote-agent, not here.
- **Streaming / token-by-token reply** — `POST /chat` returns the full `reply` at once in the contract. The typing indicator plays for the full request, not streamed chunks. Streaming is a contract change for a later iteration.
- **Voice / audio chat** — not in the contract; not in V0.3.
- **Multi-image / photo messages in chat** — `ai_messages.photo_url` is nullable and wired, but `008` does not build a "attach photo to a message" flow in the input bar; `010` will send photo + description via the same column.
- **Conversation Rename / deletion UI** — `updateConversation`/`deleteConversation` helpers exist, but chat-list swipe-to-rename/delete screens are deferred to a later pass (they're surfaced in `013-settings-profile` cleanup flows).
- **Re-prompt engineering / model selection in the app** — model and system prompt are owned by brote-agent, never surfaced to the user.
- **Onboarding Flora introduction (`012-onboarding`)** — Flora's genie-style first-launch intro is part of V1.0 onboarding, not the V0.3 foundation.
- **Health-check / status banner for brote-agent downtime** — the agent client maps `NETWORK` errors inline on send; a global "Flora está descansando" banner is not built in `008`. A `/health` call *is* wired in the client and used opportunistically (e.g. to show "online" on `/chat`), but it's a soft signal, not a blocker.
- **Conversational title summarization via the model** — the V0.3 title is just the truncated first user message (criterion 18); asking the model to title the conversation is a `010`-ish nicety.
